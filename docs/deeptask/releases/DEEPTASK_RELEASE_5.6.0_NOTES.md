# Deeptask 5.6.0

本版本聚焦长任务稳定性、终端生命周期和模型选择体验：

- 修复集成终端命令完成后活动进程引用未清理，确保完成态终端按设置数量裁剪。
- 终端仅在命令完成或扩展重启恢复时执行裁剪，运行中的命令不会被自动关闭。
- 修复命令结束、重复完成通知和旧进程回调之间的终端状态竞争。
- 左下模型选择器复用 API 设置页的动态模型目录，支持 OpenAI Compatible、Ollama、LM Studio 和 VS Code LM 的多模型选择。
- Agent 可像切换模式一样直接选择任意实时保存的配置，并可在同一配置内指定模型；用户新建或重命名配置无需重启即可使用。
- 配置与模型切换采用事务化预检：只有目标上下文容量足够且实时 API 连通成功后才保存并激活，失败时当前配置和模型均保持不变。
- 新增“提供商 / 模型”自动批准开关并默认开启；需要人工确认时可在自动批准栏独立关闭。
- 修复从 OpenAI Compatible 切换到 DeepSeek 后，下一次工具请求因不兼容的 `parallel_tool_calls` 字段返回 400 的问题。
- 修复 DeepSeek thinking 模型在多轮工具调用或跨提供商首轮续发时缺少必要推理协议字段导致的 400。
- 改善长任务续发、上下文压缩恢复和任务聚焦相关的交互稳定性。
- 修复子任务在切换模型、进入续发状态或压缩上下文后，完成时停留在子任务而没有自动返回父任务的问题。
