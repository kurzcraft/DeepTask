# Deeptask 多厂商模型列表自动更新进度

## 目标

- 不仅支持 OpenAI-compatible 自定义端点，还支持 DeepSeek 等专用厂商自动获取最新模型列表。
- 复用统一缓存、并发去重、手动刷新与失败后备机制，避免每个厂商维护独立易漂移实现。
- 用户显式输入的模型 ID 必须稳定保留；远程目录只提供候选与自动元数据，不能静默迁移。
- 模型目录失败不得阻断聊天；保留静态模型元数据作为离线后备并显示可诊断错误。

## 验收标准

- DeepSeek 新增/下线模型无需发布新扩展即可在设置中更新。
- 支持目录 API 的其他专用厂商具备同等刷新行为，而非只对 DeepSeek 特判。
- 断网、401、超时、空目录不清空已有缓存，不导致发送消息永久转圈。
- 用户手动模型 ID 始终有效；远程目录缺少该 ID 时使用安全默认元数据及用户绑定覆盖，不迁移 ID。
- 模型刷新与 Windows VS Code/VSCodium 启动均有聚焦自动化测试。

## 当前风险与否证记录

- 不同厂商的 `/models` 元数据完整度不同，远程条目必须与静态安全默认值合并。
- 部分厂商不提供模型列表 API；此类厂商只能使用官方静态目录或其 SDK 能力，不能宣称实时更新。
- 已否证：即使目录请求成功且非空，也不能据此迁移用户显式输入的模型；订阅套餐可能提供目录未列出的模型。
- 已否证：把官方动态目录视为用户配置的权威来源会破坏手填模型与订阅中转模型；目录只负责候选与元数据。
- 已否证：React Query 键包含临时 KEY 就代表请求使用了该 KEY；当前消息体没有携带它，后端仍使用旧持久值。
- 已否证：官方 `/models` 返回一定包含完整上下文；不同厂商与中转订阅返回字段差异很大，必须多字段解析并允许用户覆盖。
- 新不变量：手动模型 ID 和手动上下文属于用户显式配置，远程目录只能提供建议和元数据，不能静默覆盖。
- 新不变量：账户相关目录缓存必须按厂商、Base URL 与不可逆凭据指纹隔离，磁盘文件与日志不得包含明文 KEY。
