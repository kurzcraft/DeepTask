# Deeptask 使用指南

[返回中文主页](../../../README.md) · [English Guide](./USER_GUIDE_EN.md) · [打包与发布](./DEEPTASK_PACKAGING.md)

## 1. 安装

从 [GitHub Releases](https://github.com/kurzcraft/DeepTask/releases/latest) 下载最新的
`deeptask-*.vsix`。

在 VSCodium 中安装：

```bash
codium --install-extension ./deeptask-5.5.8.vsix --force
```

在 VS Code 中安装：

```bash
code --install-extension ./deeptask-5.5.8.vsix --force
```

也可以在扩展面板右上角菜单中选择 **Install from VSIX...**。升级后重载编辑器窗口，确认扩展列表显示新版本。

## 2. 配置模型

### OpenAI Compatible

1. 打开 Deeptask 设置，选择 **OpenAI Compatible**。
2. 填写 API Base URL、API Key 和模型 ID。
3. 使用目录刷新或模型检测读取服务端元数据。
4. 服务端未提供可靠元数据时，手动填写上下文窗口和最大输出 token。

这一路径适用于实现 OpenAI 风格 Chat Completions 或 Responses API 的云服务、代理、网关和本地推理服务。不同服务对模型 ID、鉴权头、推理参数和工具调用的支持并不完全一致；首次接入应先执行一个只读小任务，再逐步开放写文件和命令权限。

### 专用厂商

DeepSeek、Groq、Mistral 和 Cerebras 支持使用当前输入的凭据与 endpoint 刷新模型目录。模型列表按账户作用域隔离；自动目录不可用时仍可手填模型 ID，并可覆盖上下文窗口。

> API Key 仅在本地扩展配置中填写。仓库与发布包不包含用户密钥。

## 3. 选择控制方式

Deeptask 不强迫用户在“全自动”和“完全手工”之间二选一。

### 完全托管

启用 **YOLO Mode** 后，Agent 可以自动调用已开放的工具并连续推进，适合已有测试、可回滚、权限边界明确的仓库。建议仍明确给出：

- 最终产物与验收条件；
- 禁止修改的目录或接口；
- 是否允许安装依赖、提交、推送或发布；
- 长命令的日志和产物路径。

### 人机协作审查

关闭 YOLO Mode，或在自动批准设置中只开放只读、编辑、命令等特定能力。Agent 会在工具调用、命令执行和最终完成节点等待批准；用户可以批准、拒绝并附加修改意见。

推荐对陌生代码库、生产配置、数据迁移和发布任务采用逐步审批。熟悉工作流后，再按工具和命令白名单扩大自动化范围。

## 4. 驾驭长时间任务

### 在执行中持续修正

任务运行时可以继续发送新要求，不必等旧轮次结束。把新消息写成可执行变化，例如：

- “保留现有 API，不要做破坏性重构”；
- “新增移动端验收，并将截图写入 `EXTRA/output/`”；
- “暂停发布，先修复刚发现的回归测试”。

Deeptask 会把最新反馈注册为扩展、修订或替换目标，保留真实完成项，并将最新指令作为后续压缩与恢复的焦点。这里的“无限上下文”是持续压缩、持久进度和反馈接续形成的工程工作流，不代表单次模型请求拥有无限 token。

### 观察和终止后台服务

命令运行在 VS Code / VSCodium 集成终端中。多个开发服务器、测试监听器、构建或训练任务可以同时保留在终端列表，用户可随时：

1. 打开编辑器底部 **Terminal** 面板；
2. 在终端下拉列表切换到对应 Deeptask 终端；
3. 查看实时输出和原始命令；
4. 使用终端的停止、垃圾桶或 `Ctrl+C` 终止目标任务。

运行中的终端不会被“已完成终端数量”清理。默认只保留最近 3 个已完成的 Deeptask 终端，可在终端设置中调整或关闭该限制。

### 长命令与耐久日志

预计超过约 30 秒、包含多阶段操作或产生大量输出的命令，应让 Agent：

1. 在 `EXTRA/bash/` 创建任务专用脚本；
2. 将完整 stdout/stderr 写入 `EXTRA/output/`；
3. 在终端中只执行短脚本入口；
4. 完成后读取日志并根据退出状态验收。

这样既能在集成终端观察实时进度，也能在对话压缩、窗口重载或跨会话恢复后回看完整证据。

## 5. 使用 EXTRA 持续接续

`EXTRA/` 是长程任务的可恢复工作面，而不是临时杂物目录：

```text
EXTRA/
├── task/    任务清单、当前发现、决策、阻塞与验收状态
├── bash/    长命令、发布、迁移和诊断脚本
└── output/  完整日志、截图、报告、校验和与状态文件
```

对于非平凡任务，建议要求 Agent 在 `EXTRA/task/` 建立任务专用 Markdown 清单。新会话开始时先读取匹配清单，再结合 Git 状态和耐久日志恢复，不依赖模型记住所有原始对话。

历史命令可从集成终端、对话中的命令块、`EXTRA/bash/` 脚本和 `EXTRA/output/` 日志四条路径回溯。发布或迁移任务应优先保留可重复执行的脚本，而不是只留下终端文字。

## 6. 上下文压缩与恢复

Deeptask 在接近模型上下文上限时自动压缩早期对话，并在必要时回退到滑动窗口截断。为了提高恢复质量：

- 在任务开始时写清目标、约束和验收条件；
- 用任务清单记录真实状态，不把“计划”标为“完成”；
- 关键命令保留脚本和完整日志；
- 每次改变目标时明确说明新增、替换还是撤销；
- 压缩后检查最新要求仍是当前焦点，再继续高风险步骤。

压缩摘要采用事务式提交；失败摘要不会替换原历史。自动摘要失败时，运行时会优先采用可继续执行的回退策略。

## 7. 任务完成与扩展

最终结果应回答三个问题：改了什么、如何验证、还有什么边界。任务清单有未完成项或尚未进行实际工具工作时，Agent 不应提前宣布完成。

完成后继续发送要求会建立新的工作轮次，而不是重复旧结论。新要求最好明确验收增量，例如：“在现有修复基础上增加 Windows 验收，其他已通过测试不要重跑”。

## 8. 常见问题

### 消息发送后没有立即执行

检查当前是否正在等待工具批准、命令结束或取消确认。关闭 YOLO Mode 时，批准/拒绝按钮是有意的控制点；批准后任务会继续。

### 终端数量看起来很多

限制只针对已完成的 Deeptask 集成终端。仍在运行、尚未执行命令或由其他扩展/用户创建的终端不会被误删。可先在终端列表确认每项状态，再终止不再需要的后台服务。

### 模型目录为空

确认 endpoint、API Key 和账户权限，手动刷新目录。若服务不提供目录 API，可直接输入模型 ID，并按服务文档填写上下文窗口。

### 压缩后焦点不正确

立即发送一条明确的修正消息，指出当前唯一目标、应保留的完成项和应撤销的旧方向；同时更新 `EXTRA/task/` 清单。不要继续执行高风险发布或迁移步骤，直到焦点重新确认。

### 如何安全停止任务

使用 Deeptask 的取消按钮停止当前 Agent 请求；对于仍运行的后台命令，在对应集成终端中单独终止。不要无差别结束系统中的所有 Node.js、Python 或 shell 进程。
